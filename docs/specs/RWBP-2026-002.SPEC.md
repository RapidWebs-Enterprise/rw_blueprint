## 1. Purpose

`rw_blueprint` v0.2.0 establishes a canonical, machine-readable **declared** model of the
infrastructure topology (`topology.yaml`) and derives artifacts from it. But the engine is
currently **one-way**: it renders declared state outward and never observes the *live*
state of the running infrastructure.

This SPEC defines the **inbound half** of the loop — the layer that observes live state,
compares it against the declared model, and reports drift. This is the bridge between "a
source-of-truth engine" and "a self-healing system," and it is the concrete realization of
RWDN Recovery Roadmap **P4 (Observe)**.

The layer has three components:

1. **Probes** (pull) — read-only collectors that observe a fragment of live state
   (containers, services, ports, DNS, mesh peers) and emit it in a normalized shape.
2. **Watchdogs** (push) — lightweight event emitters that report changes as they happen
   (container lifecycle, config edits, mesh changes).
3. **Reconciler** — the component that diffs declared vs. observed state and emits a
   structured drift report.

The unifying contract is a **live-state schema** that is a *projection* of the topology
schema (not a parallel schema), so that declared and observed state share one vocabulary
and the diff is mechanical.

## 2. Scope

### 2.1 In Scope

- A **live-state schema** (`live_state`) that is a projection of the topology schema:
  observable entities only (nodes, services, links), with the same `id` vocabulary.
- A **probe registry** — a set of read-only collectors, each emitting a normalized
  fragment of live state. Initial probes: `incus`, `podman`, `port`, `dns`, `tailscale`.
- A **reconciler** (`rw-blueprint reconcile`) that diffs declared vs. observed state and
  emits a drift report with three-way classification (missing / extra / mismatched) plus
  severity and ignore rules.
- A **watchdog contract** — the normalized event shape that push emitters produce, and the
  security boundary that separates "emit" (untrusted, append-only) from "apply" (trusted,
  HITL-gated).
- A **live-state schema** and **drift report** that are both machine-readable (JSON/YAML)
  and agent-parseable.

### 2.2 Out of Scope

- **The autonomous agent itself** — this layer produces the drift report the agent reads;
  the agent (RWDN Recovery Roadmap P5) is a separate workstream.
- **Auto-remediation** — the reconciler SHALL NOT apply changes. It only reports drift.
  Applying a change is always HITL-gated.
- **Full watchdog implementation** — the watchdog *contract* is specified here, but the
  push emitters are sequenced as a later increment (see ADR on pull-first). The contract is
  defined now so the pull side does not paint us into a corner.
- **Secrets/credentials** — probes and watchdogs reference credentials by name only; values
  live in the credential store. No secret-bearing fields.
- **Rendering backends** — drift reports are structured data (JSON/YAML), not interactive
  HTML.

### 2.3 Assumptions

- The live infrastructure is the RWDN: one Hetzner host (`srv1`) + three Incus system
  containers (`infra`, `enterprise`, `dev`) + ~6 minimum-stack services.
- **Probes run centrally on the machine invoking `rw-blueprint reconcile`, reaching targets
  via SSH/Tailscale using the existing SSH config (keys in `~/.ssh`, `ssh` command).**
- The declared model (`topology.yaml`) is already populated and validated (RWBP-2026-001).
- Python 3.11+ is available on the host running the reconciler.

### 2.4 Constraints

- **Probes are read-only by construction** — they SHALL NOT mutate any observed system.
- **Emit is untrusted, apply is gated** — no component in this layer may write to the
  declared model; only the reconciler's *output* (drift report) is produced, and applying
  it is a separate, HITL-gated action.
- The live-state schema SHALL be a projection of the topology schema, not a parallel schema.
- Deterministic output: identical declared + observed state produces identical drift report.
- MIT license; conforms to 2026 OSS repository structure standards.

## 3. Definitions and Acronyms

| Term | Definition |
|------|------------|
| **Declared state** | The canonical `topology.yaml` — what *should* be |
| **Live/observed state** | The `live_state` document — what *is* |
| **Drift** | Any difference between declared and observed state |
| **Probe** | A read-only collector that observes a fragment of live state |
| **Watchdog** | A lightweight event emitter that reports changes as they happen |
| **Reconciler** | The component that diffs declared vs. observed and emits a drift report |
| **Projection** | A schema that is a subset of another schema's shape (same vocabulary) |
| **Missing** | Declared but not observed (e.g. a service that should run but doesn't) |
| **Extra** | Observed but not declared (e.g. an unplanned service) |
| **Mismatched** | Both exist but differ (e.g. wrong port, wrong image) |
| **HITL** | Human In The Loop — a gated approval step |
| **Splay** | Randomized schedule jitter to avoid synchronized resource spikes |

## 4. Functional Requirements

### 4.1 Functional Requirement Format

**REQ-[ID]**: [Statement of behavior]
- **Given**: [Preconditions/context]
- **When**: [Trigger/event]
- **Then**: [Expected outcome/behavior]
- **Acceptance Criteria**:
  - [Measurable, testable criteria]

### 4.2 Requirements

**REQ-001**: The system SHALL define a `live_state` schema that is a projection of the
topology schema, modeling only observable entities (nodes, services, links) with the same
`id` vocabulary as the declared model. **Live-state uses thin Pydantic subclasses of the
topology models with non-observable fields made optional.**
- **Given**: A live-state document
- **When**: The document is parsed
- **Then**: It validates against a schema whose entity shapes are a subset of the topology
  schema's entity shapes
- **Acceptance Criteria**:
  - A `live_state` document parses into `node`, `service`, and `link` objects
  - The `id` field semantics match the declared model (same stable key)
  - Zones and dependencies are absent (non-observable) or explicitly modeled as
    non-observable
  - Live-state models are thin subclasses of topology models with non-observable fields optional

**REQ-002**: The system SHALL provide a probe registry where each probe is a read-only
collector emitting a normalized fragment of live state. **Probes execute via SSH to target
hosts; timeout 30s default.**
- **Given**: A probe (e.g. `podman`) and a target host
- **When**: The probe is invoked
- **Then**: It emits a fragment of live state in the normalized `live_state` shape, and
  performs no mutation on the target
- **Acceptance Criteria**:
  - Each probe emits a fragment conforming to the `live_state` schema
  - No probe performs a mutating operation (enforced by construction and by test)
  - Probe execution uses SSH to target hosts with 30s default timeout

**REQ-003**: The system SHALL provide a `reconcile` command that diffs declared vs.
observed state and emits a drift report. **Drift report conforms to `DriftReport` schema
(JSON/YAML) with `schema_version`.**
- **Given**: A valid `topology.yaml` and a `live_state` document
- **When**: `rw-blueprint reconcile <topology> --live <live_state>` is invoked
- **Then**: A drift report is emitted classifying every difference as `missing`, `extra`,
  or `mismatched`
- **Acceptance Criteria**:
  - A declared-but-unobserved service is reported as `missing`
  - An observed-but-undeclared service is reported as `extra`
  - A service present in both but differing (port/image) is reported as `mismatched`
  - Identical declared + observed state produces an empty drift report
  - Drift report conforms to `DriftReport` schema with `schema_version` field

**REQ-004**: The system SHALL assign a severity to each drift finding. **Severity is
4-level (`critical`/`high`/`medium`/`low`); mapping to agent budget documented.**
- **Given**: A drift finding
- **When**: The drift report is produced
- **Then**: Each finding carries a severity level derived from the entity's role and the
  nature of the drift
- **Acceptance Criteria**:
  - A `missing` minimum-stack service is at least `high` severity
  - An `extra` unplanned service is at least `medium` severity
  - A cosmetic `mismatched` (e.g. description text) is `low` severity
  - Severity model is 4-level; agent budget mapping documented

**REQ-005**: The system SHALL support ignore rules that suppress known-acceptable drift.
**Ignore rules are exact-match (entity_id + field) for v0.1.**
- **Given**: A drift finding matching a declared ignore rule
- **When**: The drift report is produced
- **Then**: The finding is suppressed (or marked `ignored`) rather than reported as active
  drift
- **Acceptance Criteria**:
  - An ignore rule keyed by entity id + field suppresses that specific finding
  - Ignore rules are themselves declared (not hardcoded) and versioned
  - Ignore rules support exact-match only (entity_id + field)

**REQ-006**: The system SHALL define a normalized watchdog event contract. **Watchdog
event change_type ∈ {created, updated, deleted, restarted} for v0.1.**
- **Given**: A push emitter (watchdog) observing a change
- **When**: The change occurs
- **Then**: The emitter produces an event conforming to a normalized shape (entity id,
  change type, timestamp, payload) that the reconciler can consume
- **Acceptance Criteria**:
  - The event shape is defined and documented
  - An event can be converted into a `live_state` fragment update
  - The event shape carries no secret-bearing fields
  - `change_type` is one of: `created`, `updated`, `deleted`, `restarted`

**REQ-007**: The system SHALL enforce the emit-is-untrusted / apply-is-gated boundary.
- **Given**: Any component in this layer
- **When**: The component attempts to write to the declared model
- **Then**: The write is not permitted by the layer; only the drift report is produced, and
  applying a change is a separate HITL-gated action
- **Acceptance Criteria**:
  - No probe or watchdog has a code path that writes to `topology.yaml`
  - The reconciler's only output is the drift report (no in-place mutation of the model)

**REQ-008**: The system SHALL be deterministic. **Probe output ordering is alphabetical by
probe name.**
- **Given**: The same declared + observed state
- **When**: `reconcile` is invoked twice
- **Then**: The drift report is byte-for-byte identical
- **Acceptance Criteria**:
  - Two runs produce identical drift report output
  - Probe output ordering is alphabetical by probe name

**REQ-009**: The system SHALL reject malformed live-state documents. **Drift report
schema_version enforced.**
- **Given**: A `live_state` document with unknown fields, dangling references, or an
  unsupported schema version
- **When**: The document is parsed
- **Then**: Parsing fails with a descriptive error
- **Acceptance Criteria**:
  - Unknown fields are rejected (strict schema)
  - Dangling references are rejected
  - Unsupported `schema_version` is rejected
  - Drift report has its own `schema_version` field, enforced on parse

## 5. Non-Functional Requirements

### 5.1 Performance Requirements
- **Response Time**: `reconcile` SHALL complete in under 2 seconds for a topology of ≤ 100
  entities and a live-state of ≤ 100 entities.
- **Throughput**: Not applicable (batch CLI).
- **Scalability**: The schema SHALL remain correct for up to 1,000 entities.
- **Capacity**: No persistent state; stateless per-invocation.

### 5.2 Reliability Requirements
- **Availability**: N/A (CLI tool).
- **Fault Tolerance**: A probe that fails to reach its target SHALL emit a descriptive
  error (or a `probe_error` finding), never a crash or silent empty result. **Probe errors
  collected in `probe_errors[]`, separate from findings.**
- **Recovery**: N/A (no mutable state).
- **Data Integrity**: The live-state document SHALL round-trip losslessly.

### 5.3 Security Requirements
- **Authentication**: N/A (local CLI); probes reach targets via existing SSH/Tailscale
  trust.
- **Authorization**: Probes are read-only; no component may mutate the declared model.
- **Data Protection**: No secrets in live-state, drift report, or events.
- **Audit**: Drift findings SHALL be descriptive and deterministic.
- **Compliance**: MIT license; no regulated data.

### 5.4 Usability Requirements
- **Accessibility**: N/A (CLI).
- **Learnability**: A new user SHALL be able to run `reconcile` with a single command.
- **Efficiency**: `reconcile` SHALL be the single command for drift detection.
- **Satisfaction**: Drift findings SHALL name the exact entity and the exact difference.

### 5.5 Operational Requirements
- **Deployability**: Installable via `uv`/`pip` from `pyproject.toml`.
- **Maintainability**: Type-checked (mypy strict), linted (ruff), tested (pytest).
- **Monitorability**: The drift report is machine-readable (JSON/YAML) for downstream
  consumption by the agent.
- **Portability**: Python 3.11+; probes rely only on standard CLI tools (`incus`, `podman`,
  `ss`, `kdig`, `tailscale`).

## 6. Interfaces

### 6.1 User Interfaces
CLI via Typer: `rw-blueprint reconcile <topology> --live <live_state> [--ignore <rules>]`.

### 6.2 Hardware Interfaces
None.

### 6.3 Software Interfaces
- **APIs**: Python package `rw_blueprint.live_state` (projection schema),
  `rw_blueprint.probes` (probe registry), `rw_blueprint.reconciler` (diff engine).
- **Data Formats**: YAML input (`topology.yaml`, `live_state.yaml`); JSON/YAML drift report
  output; normalized watchdog event shape.
- **Communication Protocols**: Local filesystem; probes reach targets via SSH/Tailscale
  (read-only commands).
- **Dependencies**: Pydantic v2, PyYAML, Typer, Rich (reuse of RWBP-2026-001 stack).

## 7. Architecture Constraints

- **Language**: Python 3.11+ (consistent with ADR-003).
- **Schema**: Pydantic v2 models with `extra="forbid"`; live-state is a projection of the
  topology schema. **Live-state module uses thin subclasses; probe transport is SSH.**
- **Probes**: Read-only by construction; in-process registry (no plugin framework) per the
  probe-architecture research.
- **Reconciler**: Pure function (declared, observed) → drift report; no side effects.
- **Determinism**: Stable field ordering; no timestamps in the drift report body (timestamps
  belong in the event envelope, not the diff).
- **Separation**: The live-state schema is a projection of the topology schema; the
  reconciler is one consumer of both.

## 8. Acceptance Criteria

### 8.1 Test Scenarios
- Live-state projection schema parses (REQ-001).
- Each probe emits a conforming fragment and performs no mutation (REQ-002).
- `reconcile` classifies missing/extra/mismatched correctly (REQ-003).
- Severity assignment is correct for representative findings (REQ-004).
- Ignore rules suppress matching findings (REQ-005).
- Watchdog event shape is defined and convertible to a live-state update (REQ-006).
- No component writes to the declared model (REQ-007).
- Determinism across two runs (REQ-008).
- Malformed live-state rejected (REQ-009).

### 8.2 Success Criteria
- All functional requirements have passing tests.
- `ruff check`, `ruff format --check`, `mypy` (strict), and `pytest` all pass.
- Coverage ≥ 80%.

### 8.3 Non-Functional Test Requirements
- Round-trip losslessness test (parse → dump → parse) for live-state.
- No-secret assertion on drift report and event output.
- Probe read-only assertion (no mutating command in any probe code path).

## 9. Resolved Decisions

All open questions from v0.1.0 are resolved:

### D-01: Live-state projection mechanism → **Thin subclasses**
Live-state `Node`/`Service`/`Link` are thin Pydantic subclasses of the topology schema's
models, with non-observable fields made optional. A factory function converts declared →
live-state shape. Reuses validation logic; honestly represents that live-state may lack
`zone`, `host`, `image`, etc.; round-trip losslessness preserved.

### D-02: Probe transport → **Central-over-SSH (gateway-tier)**
Probes run centrally on the machine invoking `rw-blueprint reconcile`, reaching targets via
SSH/Tailscale using the existing SSH config (keys in `~/.ssh`, `ssh` command). RWDN is
small (1 host + 3 containers, all reachable via Tailscale); no agent deployment needed;
simpler credential model; matches "gateway tier" pattern.

### D-03: Drift report schema → **Defined as Pydantic model with versioning**
Drift report is a structured Pydantic model with its own `schema_version` (starting at
`0.1`), emitted as JSON (primary) or YAML. Contains `findings[]` (missing/extra/mismatched
with severity) and `probe_errors[]` (separate from findings).

### D-04: Probe error handling → **Separate top-level key, partial failure continues**
Probe errors are collected in `probe_errors[]` (separate from `findings[]`). Partial probe
failure continues other probes. Timeout = 30s default, configurable. Auth failure = recorded
as error, probe marked unavailable.

### D-05: Watchdog event change-type taxonomy → **Four types for v0.1**
Minimal taxonomy: `created`, `updated`, `deleted`, `restarted`. Event carries entity kind,
entity id, change type, timestamp, and payload (live-state fragment delta).

### D-06: Probe scheduling → **External (cron/systemd timer) for v0.1**
The `reconcile` command is stateless and idempotent, designed for external scheduling.
Recommended: `*/5 * * * *` with `sleep $((RANDOM % 30))` splay. Internal scheduler deferred.

### D-07: Drift report schema versioning → **Added**
Drift report has its own `schema_version` field, independent of topology/live-state versions.

### D-08: Credential reference mechanism → **SSH config for v0.1**
Probes use existing SSH config (`~/.ssh/config`, keys, `ssh` command). No additional
credential store for v0.1. Documented as assumption.

### D-09: Severity model → **4-level (critical/high/medium/low) for v0.1**
4-level is sufficient. Agent's bounded-autonomy budget maps: `critical` → immediate HITL,
`high` → next heartbeat, `medium` → next cycle, `low` → log only.

### D-10: Ignore-rule scope → **Exact-match (entity_id + field) for v0.1**
Exact-match only. Wildcards deferred.
