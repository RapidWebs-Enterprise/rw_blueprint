## Research Summary: Live-State Schema as a Projection of the Topology Model

**Source**: Kubernetes `.spec`/`.status` separation; osquery uniform-output model; reference code cloned to `~/.references/tfdrift` (models.py) and `~/.references/driftguard` (models.py)
**Date**: 2026-08-27
**Research Category**: Infrastructure Research
**Focus**: The contract that both the pull (collectors) and push (watchdogs) sides emit into — a live-state document that is a *projection* of the topology schema, not a parallel schema

### Key Findings

#### The live-state schema is a projection, not a parallel schema

The single most important design decision: the live-state document must be a **projection** of the topology schema — a subset of its entities and fields — not a separate, parallel schema. This is what makes diffing trivial and keeps the agent reasoning against one vocabulary.

The declared `topology.yaml` has five entities. The live state captures only the *observable* subset:

| Declared entity | Observable in live state? | Why |
|-----------------|---------------------------|-----|
| `zone` | No | Zones are a *design* concept, not a runtime fact |
| `node` | Yes | Hosts/containers that actually exist |
| `service` | Yes | Running workloads, actual ports/images/managed_by |
| `link` | Partial | Observable connectivity (open ports, mesh peers) |
| `dependency` | No (mostly) | Logical/operational, not directly observable |

#### The `.spec`/`.status` split is the theoretical basis

Kubernetes separates `.spec` (declared intent) from `.status` (observed reality) on the *same object*. The transferable insight: declared and observed state are *different documents* but share a *vocabulary*. `topology.yaml` is the `.spec`; `live_state` is the `.status`; and the reconciler drives `.status` toward `.spec`.

#### The observable subset is smaller than the declared model

A key consequence of the projection: the live-state schema is *strictly smaller* than the topology schema. It contains only what can be observed:

- `nodes` — what actually exists (from `incus list`)
- `services` — what's actually running (from `podman ps`), with *actual* (not declared) ports/images/managed_by
- `links` — what's actually connected (from `ss -tlnp`, `tailscale status`)

It does *not* contain zones (design concept) or dependencies (logical/operational). This asymmetry is correct and intentional: drift is precisely the difference between the *declared* full model and the *observed* subset.

#### The diff is mechanical because the vocabulary is shared

Because `live_state` uses the same field names and entity types as `topology.yaml`, the reconciler's diff is a mechanical comparison, not a per-probe bespoke transform. A `service` in `live_state` has the same shape as a `service` in `topology.yaml` — the reconciler just compares them.

#### Reference models confirm the pattern

Both cloned reference projects separate their declared and observed models:

- `tfdrift` (`~/.references/tfdrift/src/tfdrift/models.py`) — separates the *expected* (declared) resource model from the *actual* (observed) state it reads from the live system.
- `driftguard` (`~/.references/driftguard/backend/models/models.py`) — separates the declared configuration model from the collected live state, with a dedicated diff stage between them.

Both confirm: **declared model and observed state are distinct types, compared by a dedicated diff stage.**

#### The drift document is a third artifact

The output of reconciliation is a *third* document — the drift report — which is neither declared nor observed but the *difference* between them. It carries the three-way classification (missing/extra/mismatched) plus severity, and is emitted as JSON (machine) + Markdown (human).

### Implications for rw_blueprint

1. Define a **`LiveState` schema** as a projection of the topology schema (nodes/services/links only).
2. Keep the **vocabulary identical** — same field names, same entity types.
3. Emit a **`DriftReport`** as the third artifact (the diff), with three-way classification + severity.
4. Treat **zones and dependencies as non-observable** — they exist only in the declared model.
5. Emit drift as **JSON (machine) + Markdown (human)**.
