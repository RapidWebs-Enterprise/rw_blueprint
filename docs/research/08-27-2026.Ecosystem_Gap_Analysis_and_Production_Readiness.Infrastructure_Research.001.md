## Research Summary: Ecosystem Gap Analysis — rw_blueprint vs. the 2026 topology-as-code + drift-detection field

**Source**: Cross-project comparison against Shumoku, Marrow, TopoViewer, netviz, iso-topology, awslabs/diagram-as-code, drawio-mcp-server, Dorikin, StateSight, KubeVerdict, kube-diff, kdrift, kube-compare, Kausality, statedrift, gitops-drift-remediation-agent, OpenSentinel, InfraIgnite, BlastRadius, provenance-template, Repomatic; plus FastMCP / official MCP Python SDK, Python Packaging User Guide (entry points), SUEWS schema-versioning, rack2cloud IaC-auditability, Kosli provenance.
**Date**: 2026-08-27
**Research Category**: Infrastructure Research
**Focus**: What critical features and tooling is `rw_blueprint` missing relative to the mature field, and what is required to prepare it for expansion and production use

### Key Findings

#### Verdict up front

`rw_blueprint` is **architecturally sound and ahead of the field on the declared-vs-observed core** — the five-entity model, the live-state projection, the three-way drift classification, and the emit-untrusted/apply-gated boundary are all independently re-derived by the best projects surveyed (KubeVerdict's "anchor-by-render", StateSight's "desired vs live", Kausality's "declared vs intended"). But it is missing **three table-stakes capabilities** and a cluster of expansion/production gaps that every serious comparable ships.

#### The three headline gaps

**G1 — No MCP server (the single biggest miss).** The tool's stated purpose is to give agents "something real and physical to use objectively", yet there is no MCP interface — an agent can only shell out to the CLI. Every comparable ships one: iso-topology exposes 7 MCP tools, drawio-mcp-server 20, awslabs/diagram-as-code ships `awsdac-mcp-server`, kdrift 4. FastMCP is now the standard (per Prefect, some version powers ~70% of MCP servers across languages), and its `@mcp.tool()` decorator auto-generates the JSON Schema *from existing type hints*. The four verbs (`validate`, `generate`, `probe`, `reconcile`) map 1:1 to MCP tools. The security model already committed in ADR-011 (apply-is-gated) maps directly onto MCP's own contract (tools require user approval before execution).

**G2 — No machine-readable output + no CI exit codes.** The reconciler emits a Rich table (human-only). The entire P5-agent rationale was "parse a JSON report at a moment's notice", but there is no `--format json` and no `--exit-code`. kube-diff, kdrift, and BlastRadius all converge on the identical contract: `0` = clean, `1` = drift/violation, `2` = error, with `--format json` for machines and `--exit-code`/`--check` to gate CI. This is the literal bridge between P4 (observe) and P5 (automate).

**G3 — No supply-chain security (DEFERRED by user: distribution waits until internal adoption succeeds).** provenance-template and Repomatic define the 2026 production bar — SBOM (CycloneDX), Sigstore keyless signing, SLSA provenance, OSV/pip-audit scanning, gitleaks, zizmor, Trusted Publishing (OIDC), pinned Actions. Explicitly out of scope for now; recorded here so the gap is not forgotten.

#### Expansion-readiness gaps

**G4 — Schema migration (enforce-but-cannot-upgrade).** `schema_version` is enforced (excellent anti-drift), but the schema already went 0.1→0.2 and there is no upgrade path — old `topology.yaml` files are stranded. SUEWS is the reference: a chained migration-handler registry, a `migrate` command with `--dry-run` and `--target-version`, and the rule that **additive changes do not bump the schema; breaking changes bump + register a handler**. Marrow ships `import`/`--target-version` for the same reason. versionedconfig (Go) chains `UpgradeTo` functions oldest→newest.

**G5 — No probe extensibility path.** ADR-010 correctly rejected a plugin framework for ~5 first-party probes, but "prepare for expansion" requires a fork-free way to add probes. `importlib.metadata.entry_points` is the stdlib (since 3.8) canonical "creating and discovering plugins" mechanism per PyPA; Shumoku uses a plugin SDK for data-source plugins; click-plugins shows the standard "BrokenCommand" pattern so a bad plugin can't break the CLI. A `rw_blueprint.probes` entry-point group gives third-party probes without a framework dependency and without forking.

**G6 — No remediation artifact.** The reconciler reports drift but produces no structured fix. driftguard, KubeVerdict, gitops-drift-remediation-agent, OpenSentinel, InfraIgnite, and the AWS drift-detection sample all converge: remediation = **minimal diff + blast-radius estimate + severity + human gate**, never auto-apply. Two load-bearing findings: gitops-drift-remediation-agent computes *minimal* JSON Patches ("smallest possible diff, never full resource replacement") and enforces least-privilege (never delete/create); OpenSentinel found LLM-generated patches are *structurally valid but sometimes semantically wrong*, so **human review is non-negotiable** — this is the empirical case for the emit-untrusted/apply-gated boundary already in ADR-011.

**G7 — No provenance/ownership attribution.** The reconciler answers "what drifted" but not "what caused it." Kausality's tagline — "every mutation needs a cause" — and its central insight ("declarative systems converge to declared state, not intended state") is the sharpest finding in the whole survey. Kosli attributes every change to an actor (pipeline vs clickops) with fingerprinting; statedrift snapshots host state into a tamper-evident hash chain. rack2cloud's "idempotency ≠ auditability" argues the evidence artifact (approved intent → authorization event → signed plan → policy snapshot → execution record) is the unit of auditability. **Scoping note:** full tamper-evident chains and authorization-chain capture are a *later* phase (the P5 agent / a dedicated evidence tool), not this increment — but the live-state schema should capture origin metadata (observed timestamp, probe source) now so provenance isn't retrofitted later.

#### Secondary feature gaps

| # | Gap | Reference pattern |
|---|-----|-------------------|
| G8 | `--watch` continuous mode | Dorikin auto-refresh, kube-diff watch, kdrift `--watch` |
| G9 | Historical drift tracking / trend | Dorikin "track drift over time" |
| G10 | `validate` "did you mean" + line-numbered fix hints + exit 0/2/3 | Marrow, iso-topology |
| G11 | Layered views (L1/L2/L3) | netviz `--layer`, TopoViewer layers |
| G12 | Hostile-content fuzz tests (hostile YAML/Markdown/SVG input) | TopoViewer |
| G13 | Deterministic/golden-file output tests | iso-topology "byte-deterministic" output |

### Prioritized recommendation

The gaps are *not* "do all 13 now". They sequence into three waves:

1. **Now (unlocks the stated mission, low effort):** G1 MCP server · G2 JSON + exit codes · G6 remediation artifact.
2. **Next (production readiness, pre-distribution):** G3 supply-chain security · G4 schema migration.
3. **Then (expansion, as the fleet grows):** G5 entry-points plugins · G7 provenance · G8–G13.

The dependency logic is unchanged from prior research: **the agent is the reward for finishing observe → propose → gate**, not a shortcut around it. G1/G2/G6 complete the observe→propose half of that loop; the apply half remains gated by ADR-011.
