## Research Summary: Agent Integration Surface for a Source-of-Truth Topology Model

**Source**: Prajwal Ravi "Network Topology as Code"; Itential source-of-truth research; blast-radius / bounded-autonomy patterns from the RWDN recovery roadmap  
**Date**: 2026-08-27  
**Research Category**: Infrastructure Research  
**Focus**: How an autonomous (or semi-autonomous) agent reads, diffs, and proposes changes to the canonical topology model — the "objective reality" requirement

### Key Findings

#### The agent needs a single objective file to reason against

The core requirement is that an agent must not reason against prose. Prose drifts; the agent then faithfully reproduces the drift. The canonical YAML model is the fix: it is the *only* thing the agent reads as ground truth.

#### Three agent operations the model must support

1. **Read** — the agent loads `topology.yaml` and reasons about the declared state. This requires the model to be complete and self-describing (see schema design report).

2. **Diff** — the agent compares the declared model against *live* state (probes, `incus list`, `podman ps`, DNS queries) and produces a drift report. This is the "detect infrastructure problems" capability.

3. **Propose** — the agent proposes a change as a *YAML diff* (add a node, change a port, add a dependency). The diff is reviewable by a human before application — this is the human-in-the-loop gate.

#### The autonomy surface is a design problem, not a coding problem

The agent can only be trusted to "auto-fix" if there is a hard allowlist of what it may touch and a hard always-escalate list of what it may never touch without a human. The model directly supports this by making the *blast radius* of any change computable:

| Change class | Blast radius | Autonomy |
|--------------|--------------|----------|
| Read-only diagnostics | none | auto |
| Restart a known-good service | single service | auto (startup phase) |
| Apply a pre-approved config change | single service | auto (startup phase) |
| DNS / firewall / auth / mesh change | network-wide | always HITL |

Because the model encodes `dependencies` and `zones`, the blast radius of any proposed diff can be *computed* — a node's dependents, a zone's members — rather than guessed.

#### The dependency chain: the agent is the last thing built

The agent cannot be built on a fragile, non-reproducible stack. It requires three prerequisites to exist first:

1. **A declarative source of truth** (the YAML model) — so "drift" is detectable.
2. **Observability** (probes, health checks, JSON output) — so "problems" are detectable.
3. **A safe action surface** (allowlist + always-escalate list) — so "auto-fix" is bounded.

This yields the dependency chain: **Stabilize → Reproduce → Rebuild clean → Observe → Automate**. The agent is the reward for finishing the first four phases, not a shortcut around them.

#### Heartbeat architecture (multi-train)

The agent's wake cadence is not a single interval but multiple independent trains:

- **Hourly infra-health loop** — coarse overall health.
- **Faster probe loop** — once a probe tool exists that writes a JSON status file the agent can parse at a moment's notice.

Each train has a bounded budget (turns × wall-time × frequency = cost ceiling), and anything exceeding the budget escalates to an administrator via email or a ticket system.

#### Integration surface summary

| Surface | Mechanism | Consumer |
|---------|-----------|----------|
| Canonical model | `topology.yaml` (git-versioned) | agent (read), humans (review) |
| Drift report | `diff` command output | agent (detect), humans (review) |
| Proposed change | YAML diff | agent (propose), human (approve) |
| Live state | probe JSON | agent (parse), observability |
