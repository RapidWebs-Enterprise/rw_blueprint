Core Capabilities

Everything you need to manage infrastructure with confidence.

📋

Validate

Check topology YAML against a strict Pydantic schema with comprehensive error reporting.

⚡

Generate

Produce quadlet containers, Incus profiles, Mermaid diagrams, and documentation from topology.

🔍

Probe

Run read-only infrastructure probes (ports, Incus, podman, DNS, Tailscale) across multiple nodes.

📊

Reconcile

Three-way drift classification: missing, extra, and mismatched entities with severity levels.

🚀

Deploy

Execute deployment plans with dependency ordering, health checks, and automatic rollback.

🖼️

Image Lifecycle

Build, pull, push, inspect, and prune container images with security validation.

CLI Reference

Powerful commands for infrastructure management.

# Basic validation rw-blueprint validate topology.yaml # Output: # Valid topology 'rapidwebs-rwdn' (7 nodes, 11 services). # Validate with strict mode rw-blueprint validate topology.yaml --strict
# Generate all artifacts rw-blueprint generate topology.yaml --output docs/generated/ # Generated structure: # docs/generated/ # ├── quadlet/ # Podman systemd units # │ ├── pgvector.container # │ └── honcho-api.container # ├── diagrams/ # Mermaid visualizations # └── docs/ # Markdown documentation
# Run probes on multiple nodes rw-blueprint probe --nodes srv1,infra,enterprise,dev # Run specific probes only rw-blueprint probe --probes incus,podman,port --nodes infra # Save to file rw-blueprint probe --nodes all --output docs/live-state.json
# Preview deployment (dry-run) rw-blueprint deploy topology.yaml --node infra --dry-run # Deploy with auto-rollback rw-blueprint deploy topology.yaml --node infra # Deploy specific services rw-blueprint deploy topology.yaml --node infra --services honcho-api,caddy # Force deploy (skip confirmation + auto-rollback) rw-blueprint deploy topology.yaml --node infra --force
# List images on node rw-blueprint image list --node infra # Build from source rw-blueprint image build honcho-api \ --source /home/sysop/honcho \ --node infra # Pull from registry rw-blueprint image pull honcho:latest \ --registry ghcr.io # Prune old images rw-blueprint image prune --node infra --keep-latest 5
# Start MCP server (stdio) uv run rw-blueprint mcp # Start MCP server (HTTP/SSE) uv run rw-blueprint mcp --http # MCP Tools available: # - validate_topology # - generate_artifacts_tool # - run_probes # - reconcile_topology

Frequently Asked Questions

Common questions about rw_blueprint.

topology.yaml is the single source of truth. It defines your desired infrastructure state using a declarative YAML schema. rw_blueprint validates this file, generates artifacts from it, and continuously compares it against live infrastructure to detect drift.
The reconciler compares your declared topology against live infrastructure state collected by probes. It classifies differences into three categories: missing (declared but absent), extra (present but not declared), and mismatched (different attributes). Each drift item has a severity level: critical, warning, or info.
No. Per ADR-0015, all deployment changes are gated behind human approval. You can preview changes with --dry-run, confirm before applying, and enable auto-rollback if health checks fail. This follows the "emit untrusted, apply gated" security model.
rw_blueprint supports any node reachable via SSH. Tested with:
  • Hetzner VMs (srv1)
  • Incus containers (infra, enterprise, dev)
  • Local workstations
  • Any Linux host with SSH access
Currently rw_blueprint generates Podman quadlet units and Incus profiles. Kubernetes support is on the roadmap (Phase 2). You can extend the generator with custom templates for other platforms.
See CONTRIBUTING.md for guidelines. We follow Conventional Commits and require tests for all changes. Run uv run pytest before submitting PRs.
