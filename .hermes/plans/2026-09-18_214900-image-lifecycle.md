# Image Lifecycle Feature — Spec & Plan

> **For Hermes:** Use `plan-and-audit` skill (MEDIUM mode) for implementation.

**Goal:** Add automated image lifecycle management to rw_blueprint — build, pull, tag with version, push, and track which fork version is deployed.

**Architecture:** Extend the deployer module with an `ImageLifecycle` class that handles:
- Image inspection (what's locally available, with metadata)
- Image pulling from remote registries
- Image building from source (git repo + Containerfile)
- Image tagging (semantic version + git SHA + semantic labels)
- Image pushing to registry
- Version tracking (which commit → which image tag)

**Tech Stack:** Python 3.11+, podman CLI, git CLI, pydantic models

## Spec: Image Lifecycle Interface

### 1. Model Definitions

```python
@dataclass(frozen=True)
class ImageRef:
    """Reference to a container image with metadata."""
    name: str                    # e.g., "localhost/honcho"
    tag: str                     # e.g., "v2.1.3", "a7b3c9d", "latest"
    digest: str | None = None    # e.g., "sha256:..."
    source: str                  # "build", "pull", "load"
    built_at: datetime | None = None
    git_sha: str | None = None   # commit SHA used for build
    git_repo: str | None = None  # source repo URL
    labels: dict[str, str] = field(default_factory=dict)
```

### 2. CLI Commands

```bash
# Inspect local images
rw-blueprint image list [--node infra]

# Inspect specific image
rw-blueprint image inspect honcho-api

# Pull image from registry
rw-blueprint image pull honcho-api --registry ghcr.io --tag v2.1.3

# Build image from source
rw-blueprint image build honcho-api \
  --source /home/sysop/honcho \
  --tag v2.1.4 \
  --label git.sha=$(git rev-parse HEAD)

# Push image to registry
rw-blueprint image push honcho-api --tag v2.1.4

# Deploy with version pinning
rw-blueprint deploy topology.yaml --node infra --pin-version
```

### 3. Topology Schema Extension

```yaml
services:
  - id: honcho-api
    image: localhost/honcho:latest
    image_config:
      source: ghcr.io/rapidwebs-ent/honcho  # where to pull from
      build_context: /home/sysop/honcho     # where to build from
      tag_strategy: git-sha                 # git-sha | semver | latest
      labels:
        org.opencontainers.image.source: "https://github.com/RapidWebs-Enterprise/honcho"
```

## Implementation Plan (Medium Mode)

### Phase 1: Foundation (2 tasks)
**Goal:** Model definitions + CLI scaffolding

#### Task 1.1: Add ImageConfig to schema
- **Files:** `src/rw_blueprint/schema.py`, `tests/test_schema.py`
- **Changes:**
  - Add `ImageConfig` dataclass with fields: source, build_context, tag_strategy, labels
  - Add optional `image_config` field to `Service` model
  - Update YAML parser to accept new field
- **Tests:** Validation of ImageConfig, optional field handling

#### Task 1.2: CLI image subcommand
- **Files:** `src/rw_blueprint/cli.py`, `tests/test_cli.py`
- **Changes:**
  - Add `@app.group()` for image commands
  - Implement `image list`, `image inspect`, `image pull`, `image build`, `image push` stubs
  - Each stub raises `NotImplementedError` initially
- **Tests:** CLI invocation, help output, error messages

### Phase 2: Core Operations (3 tasks)
**Goal:** Working image lifecycle operations

#### Task 2.1: Image inspection
- **Files:** `src/rw_blueprint/deployer/lifecycle.py`
- **Changes:**
  - Implement `list_images(node: str)` — run `podman images` on target
  - Implement `inspect_image(node: str, image_ref: ImageRef)` — get metadata
  - Parse podman output into ImageRef objects
  - Extract labels (git.sha, version, etc.)
- **Tests:** Mock SSH responses, parse various image metadata formats

#### Task 2.2: Image pull
- **Files:** `src/rw_blueprint/deployer/lifecycle.py`
- **Changes:**
  - Implement `pull_image(node, image_ref)` — run `podman pull`
  - Handle authentication (config from ~/.containers/auth.json)
  - Verify pulled image with `podman inspect`
  - Log pull operation to deployments.json
- **Tests:** Mock pull success/failure, auth handling

#### Task 2.3: Image build
- **Files:** `src/rw_blueprint/deployer/lifecycle.py`, `src/rw_blueprint/templates/Containerfile.j2`
- **Changes:**
  - Implement `build_image(node, image_ref, context_path)`
  - Generate Containerfile from template if not provided
  - Tag with git SHA + semantic tags
  - Add OCI labels for traceability
  - Handle build args (--build-arg)
- **Template:** Auto-generate Containerfile from topology service definition
- **Tests:** Build success, tag generation, label injection

### Phase 3: Integration (2 tasks)
**Goal:** Connect lifecycle to deployer

#### Task 3.1: Executor integration
- **Files:** `src/rw_blueprint/deployer/executor.py`
- **Changes:**
  - Add `_ensure_image()` method to DeployExecutor
  - Check if image exists locally on target
  - If missing, call lifecycle to pull or build
  - Log image version to deployment state
- **Tests:** Mock executor with missing image, verify lifecycle called

#### Task 3.2: Quadlet template fix
- **Files:** `src/rw_blueprint/templates/quadlet.container.j2`
- **Changes:**
  - Add env_vars loop to emit Environment= lines
  - Support optional environment config
  - Preserve existing structure
- **Tests:** Template rendering with/without env vars

### Phase 4: Version Tracking (1 task)
**Goal:** Track which fork commit is deployed

#### Task 4.1: Version pinning
- **Files:** `src/rw_blueprint/deployer/state.py`, `.rw_blueprint/deployments/`
- **Changes:**
  - Add `pinned_version` field to deployment state
  - Store git SHA + timestamp in deployment history
  - Display version in `rw-blueprint deploy --plan` output
- **Tests:** State serialization, version tracking across deployments

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| podman CLI version mismatch | Medium | Version check at startup, fallback to API |
| Large images slow transfer | High | Compress before SCP, or build on target |
| Network failure during pull | Medium | Retry with exponential backoff |
| Disk space exhaustion | High | Check available space before build |
| Auth failures for private registry | Medium | Clear error messages, hint at fix |
